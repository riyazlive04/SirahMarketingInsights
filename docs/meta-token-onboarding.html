Ayn Onboarding guide

Connect your Meta ad account

Generate a permanent access token so Ayn can read your ad performance. One-time setup, about ten minutes. The token never expires, so you will not have to do this again.

Ayn · Sirah Digital · ayn.sirahagents.com

Read-only, always. Ayn requests the ads_read permission and nothing else. It cannot create, edit, pause or spend on your campaigns. You can revoke access at any time by deleting the System User created in step 4.

Before you start

  • You must be an admin of the Meta Business that owns the ad account. If you only have access to the ad account itself, ask your Business admin to run this.
  • Have your ad account name to hand — you will pick it from a list.
  • Use a desktop browser. The Business Settings interface does not work well on mobile.
1

Create a Meta app

Go to developers.facebook.com/apps and click Create app.

When asked what you want your app to do, choose Other, then Business as the app type. Name it something you will recognise later, such as “Ayn Reporting”. Attach it to your Business portfolio when prompted.

developers.facebook.com/apps → Create app → Other → Business
Screenshot 1
The “Create an app” type selector, with Business selected.
2

Add the Marketing API

On your new app’s dashboard, scroll the product list to Marketing API and click Set up. Nothing further to configure here — the product just needs to be present on the app.

Screenshot 2
The app dashboard product list, with the Marketing API “Set up” button visible.
3

Open Business Settings

Go to business.facebook.com/settings. If you manage more than one business, use the switcher at the top left to select the one that owns the ad account you want to report on.

Screenshot 3
Business Settings, with the business switcher open.
4

Create a System User

In the left sidebar, open Users → System Users, then click Add.

Name it Ayn Reporting and set the role to Employee. Employee is sufficient for reading performance data — Admin is not needed.

Business Settings → Users → System Users → Add
Screenshot 4
The “Create system user” dialog with the name filled in and the Employee role selected.
5

Assign your ad account to it

Most commonly missed step

With the new System User selected, click Assign assets. Choose Ad Accounts, tick the account you want reported on, and enable View Performance. Save.

Skip this and everything still appears to work — the token generates, Ayn accepts it — but it reads no ad accounts and your dashboard stays empty.

System user → Assign assets → Ad Accounts → [your account] → View Performance
Screenshot 5
The asset assignment panel with an ad account ticked and the View Performance toggle on.
6

Assign the app to it

Still on the System User, click Assign assets again. This time choose Apps, tick the app you created in step 1, and enable Manage app. Save.

System user → Assign assets → Apps → [your app] → Manage app
Screenshot 6
The asset assignment panel on the Apps tab, with the app ticked.
7

Generate the token

Shown only once

Click Generate new token. Select the app from step 1, then tick ads_read in the permission list. Leave every other permission unticked.

Meta displays the token exactly once. Copy it now — if you close the dialog without copying, you must generate a new one.

System user → Generate new token → [your app] → ads_read → Generate
Screenshot 7
The token dialog with ads_read ticked, and the generated token with the Copy button. Blur the token itself before sharing this screenshot.
8

Paste it into Ayn

Sign in at ayn.sirahagents.com with your Google account. On the Ad account screen, open “Or connect with a permanent access token”, paste the token, and press Connect.

Ayn checks the token against Meta before saving it, so a bad paste fails immediately with the reason. Once accepted, your ad accounts are listed and the dashboard fills with your live numbers.

Screenshot 8
The Ayn setup screen after a successful connection, showing the listed ad accounts.

If something goes wrong

What you seeWhat it means
“The token is valid but reaches no ad accounts.” Step 5 was missed, or the wrong ad account was ticked. Reopen the System User, assign the ad account with View Performance, and paste the same token again.
“That does not look like a Meta access token.” Part of the token was cut off when copying. Generate a new one and copy the whole string.
“Meta rejected this token.” The token was revoked, or it was generated against an app that is not assigned to the System User. Redo steps 6 and 7.
No System Users item in the sidebar You are not an admin of this Business. Ask whoever set it up to run this guide, or to make you an admin.
The ad account is missing from the list in step 5 The ad account is owned by a different Business than the one you are in. Switch business at the top left and try again.

How your token is handled

The token is encrypted with AES-256-GCM before it is written to the database, and is never sent back to a browser — not to yours, not to anyone else’s. Ayn calls Meta from its own server, so the token never reaches the page you are looking at. It is used only to read reporting data for the ad accounts you assigned in step 5.

To revoke access at any time: Business Settings → Users → System Users → select Ayn Reporting → Remove. The dashboard stops updating immediately and Ayn will ask you to reconnect.
